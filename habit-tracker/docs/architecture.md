# Архитектура проекта

## Общая схема

Приложение построено по классической схеме клиент-сервер:

```
Браузер (клиент) → Flask-сервер → SQLite (хранилище)
```

Сервер реализован как Flask-приложение с разделением на модули
(паттерн "фабрика приложения" + Blueprint), что упрощает тестирование и
дальнейшее расширение проекта.

## Структура проекта

```
habit-tracker/
├── app/
│   ├── __init__.py        # фабрика приложения (create_app)
│   ├── db.py               # подключение к SQLite, инициализация схемы
│   ├── routes.py            # все маршруты (Blueprint "habits")
│   ├── validation.py        # функции валидации входных данных
│   ├── templates/           # HTML-шаблоны (Jinja2)
│   └── static/css/          # стили
├── tests/                    # тесты pytest
├── docs/                      # документация
├── run.py                      # точка входа
└── requirements.txt
```

## Почему выбраны эти технологии

- **Flask** — лёгкий веб-фреймворк, идеально подходит для небольшого
  прототипа: минимум "магии", весь код приложения прозрачен и понятен.
- **SQLite** — файловая база данных, не требует отдельного сервера БД,
  удобна для учебного проекта и легко переносится вместе с репозиторием.
- **Jinja2** (встроен в Flask) — шаблонизатор для генерации HTML,
  позволяет избежать дублирования кода через `base.html`.
- **Bootstrap 5** (через CDN) — готовый набор CSS-компонентов, чтобы
  не тратить время на вёрстку и получить аккуратный интерфейс.
- **pytest** — стандарт для тестирования Python-приложений, простой
  синтаксис тестов через `assert`.

## Разделение на модули

- `db.py` — вся работа с базой данных изолирована здесь. Если в будущем
  понадобится перейти на другую БД (например, PostgreSQL), достаточно
  изменить только этот файл.
- `validation.py` — отдельный модуль для проверки данных форм. Благодаря
  этому валидацию легко покрыть unit-тестами независимо от Flask.
- `routes.py` — все HTTP-маршруты собраны в одном Blueprint, что облегчает
  навигацию по коду.

## Поток данных при отметке привычки

1. Пользователь нажимает кнопку "Отметить выполнение" на странице.
2. Браузер отправляет POST-запрос на `/habit/<id>/log`.
3. Flask-сервер проверяет, не превышен ли дневной лимит (`target_count`).
4. Если лимит не превышен — добавляется новая строка в таблицу `logs`
   с сегодняшней датой.
5. Пользователь возвращается на предыдущую страницу с обновлённым
   прогресс-баром.
